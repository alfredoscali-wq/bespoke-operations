# Bespoke Operations Product Handbook

Versión: 1.0

Estado: Activo

---

## ¿Qué es este documento?

El Bespoke Product Handbook representa la documentación oficial del producto.

Su objetivo es definir la visión, la arquitectura, los principios y las decisiones que gobiernan el desarrollo de Bespoke Operations.

El Handbook no describe únicamente el estado actual del software.

Describe el producto que estamos construyendo.

Cuando exista una diferencia entre la implementación y este Handbook, deberá analizarse si el código necesita evolucionar o si la decisión arquitectónica debe actualizarse.

---

## Objetivos

Este Handbook busca:

- Definir una visión única del producto.
- Mantener una arquitectura consistente.
- Evitar duplicación de criterios entre módulos.
- Documentar las decisiones importantes.
- Facilitar la incorporación de nuevos desarrolladores.
- Servir como contexto permanente para herramientas de IA como Cursor.

---

## Organización

El Handbook se encuentra organizado en capítulos.

### 01 - Producto

Describe la visión general del sistema.

Incluye:

- Product Vision
- System Overview
- Roadmap
- Product Decisions

### 02 - Arquitectura

Describe los Core Engines del sistema.

### 03 - Principios

Define las reglas de diseño del producto.

### 04 - Dominio

Describe el modelo de negocio, entidades, relaciones y reglas.

### 05 - Módulos

Documenta cada módulo funcional.

### 06 - Procesos

Documenta los procesos de negocio.

### 07 - ADR

Registra todas las decisiones de arquitectura.

---

## Regla principal

El código implementa el Handbook.

El Handbook no intenta describir el código.
